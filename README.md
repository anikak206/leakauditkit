## Why

LLM benchmark scores are inflated by train/test contamination. Tabular ML models
cheat via feature leakage. Most teams discover this *after* shipping. LeakAuditKit
is a small, dependency-light CLI that runs two complementary detectors:

- **N-gram detector** — verbatim / near-verbatim overlap (Jaccard over n-grams,
  optional IDF weighting, doc-frequency filtering).
- **Semantic detector** — embedding cosine similarity (sentence-transformers,
  optional dependency).

It emits JSON / Markdown / self-contained HTML scorecards with per-pair evidence.

## Install

```bash
pip install -e .            # core (n-gram detector, CLI)
pip install -e .[semantic]  # + embedding detector
pip install -e .[dev]       # + tests/lint
```

## One-command demo

```bash
leakaudit audit --train examples/train.jsonl --eval examples/eval.jsonl --detector all --format all --output ./audit_report
```

Docker:

```bash
docker build -t leakauditkit .
docker run --rm -v "$PWD:/data" leakauditkit audit --train /data/examples/train.jsonl --eval /data/examples/eval.jsonl --detector ngram
```

## Commands

```bash
leakaudit audit       --train T --eval E --detector all --format all
leakaudit benchmark  --output ./bench --n-train 60 --n-eval 60
leakaudit shortcuts  --input preds.jsonl --text-key text --feature-keys src
leakaudit graph      --input report.json --output graph.json
leakaudit audit-hf   --train-dataset org/train --eval-dataset org/bench
```

## Detectors

| Detector | Deps | Best for |
|---|---|---|
| ngram | none (stdlib) | Verbatim / near-verbatim leakage |
| tfidf | scikit-learn (core) | Paraphrased leakage, zero heavy deps |
| semantic | sentence-transformers (optional) | Deep semantic contamination |

## Deployment

- **FastAPI service:** `uvicorn leakauditkit.api:app`
- **HF Space:** `app.py` (Gradio) — deploy to Hugging Face Spaces
- **Docker:** `docker build -t leakauditkit .`

## Architecture

```
src/leakauditkit/
  cli.py            Click CLI
  config.py         Pydantic config models
  loaders.py        jsonl / csv / json / HF loaders
  detectors/
    base.py         BaseDetector + result models
    ngram.py        N-gram overlap (IDF-weighted Jaccard)
    semantic.py     Embedding cosine (lazy import)
  report.py         JSON / Markdown / HTML scorecards
```

## Benchmark (measured)

Synthetic benchmark: 60 train / 60 eval items, 25% contamination, seed=42.
Detector: N-gram (n=5, threshold=0.3, min_shared=3). Semantic detector
requires `sentence-transformers` (not installed in this environment).

| Scenario | Precision | Recall | F1 | TP | FP | FN |
|---|---|---|---|---|---|---|
| verbatim_25 | 1.000 | 1.000 | 1.000 | 15 | 0 | 0 |
| partial_25 | 1.000 | 0.467 | 0.636 | 7 | 0 | 8 |
| mixed_25 | 1.000 | 0.667 | 0.800 | 10 | 0 | 5 |
| clean_0 | 1.000 | 1.000 | 1.000 | 0 | 0 | 0 |

Interpretation: the n-gram detector has **zero false positives** across all
scenarios (precision 1.0) but misses paraphrased/partial leakage (recall 0.47 on
partial). This is the honest trade-off: lexical detection is conservative;
semantic detection (optional) is needed for paraphrased contamination. Threshold
sweep plots are generated by `leakaudit benchmark`.

## Limitations

- Semantic detector requires `sentence-transformers` (heavy, optional).
- N-gram detector is lexical: paraphrased leakage (semantic, non-lexical) is
  only caught by the semantic detector.
- No cross-lingual support yet.
- Thresholds are heuristic; calibrate on your domain.
